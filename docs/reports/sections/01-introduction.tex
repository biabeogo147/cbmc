\section{Introduction}
\label{sec:introduction}

OSEK/VDX is an operating-system standard for vehicle-mounted software~\cite{osek_spec}. An
application developed on OSEK/VDX OS consists of multiple tasks. To concurrently execute
multiple tasks on one CPU, OSEK/VDX scheduler uses task states, priorities, and a ready
queue to determine the running task. In contrast with many forms of concurrent software in
which the running thread is not explicitly controlled by the application, OSEK/VDX applications are dispatched by a deterministic scheduler. OSEK/VDX OS also provides standardized application interfaces (APIs), such as \texttt{ActivateTask}, \texttt{TerminateTask}, \texttt{SetEvent}, and \texttt{WaitEvent}, through which tasks can dynamically change task states, events, and the task execution order.

To ensure the reliability of OSEK/VDX applications, the behaviours of the OSEK/VDX scheduler should be taken into account in the verification process. Testing is an important checking technique used in industry, but it is difficult to exhaustively check OSEK/VDX applications using testing technique, especially because of incomplete test-cases. In addition, it is hard to reproduce an error trace when an error is detected by testing, due to the concurrency of OSEK/VDX applications.

The main difficulty is accuracy. Existing model checking methods for concurrent software
usually check all of the interleavings of threads. If such methods are applied directly to
OSEK/VDX applications, the verification process becomes too imprecise because the behaviours
of OSEK/VDX scheduler are not taken into account. As a result, a large number of unnecessary interleavings of tasks may be checked in the verification stage, which can lead to spurious bugs and increases the checking costs in terms of time and memory. Therefore, a more accurate bounded model checking approach for OSEK/VDX applications should take into account the deterministic scheduler, the ready queue, and the standardized application interfaces (APIs).

This report describes a CBMC-based checking approach that addresses this problem in two parts. First, the APIs invoked from tasks are taken into account during the verification process, so that the states of tasks, synchronization events, shared resources, and task execution order can be handled according to the behaviours of the OSEK/VDX scheduler. Second, the checking model is constructed to avoid exploring unnecessary behaviours in the verification stage.

The report makes three contributions:

\begin{itemize}[leftmargin=1.5em]
  \item It describes how bounded model checking can be specialized for OSEK/VDX applications whose tasks are dispatched by a deterministic scheduler.
  \item It introduces a manifest for building a new checking model with interrupt-service-routine calls only at manifest-listed program locations.
  \item It presents benchmark results showing that the proposed approach reduces unnecessary task interleavings and removes spurious bugs reported by the baseline.
\end{itemize}

The rest of this report is structured as follows. \Cref{sec:background} presents the OSEK/VDX execution model and the role of bounded model checking. \Cref{sec:method} describes the proposed checking approach. \Cref{sec:evaluation} reports the benchmark results and discusses the accuracy and checking costs of the approach. \Cref{sec:discussion} summarizes the main limitations of the current implementation.
